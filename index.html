About this demo

What it shows

“Wireless” isn’t magic — it’s just bytes with a checksum. One board broadcasts a fixed 32-byte packet a few times a second; a second board, plugged into the laptop, catches each one and shows it here: the raw bytes (colored by field), the decoded values, and how many packets arrive, how many go missing, and how strong the signal is.

Try this during the tour: walk the sending board toward the back of the room and watch last RSSI drop and the loss counter climb. Step between the two boards with your body and the little dot flashes as packets go missing.

How it works

TX broadcasts a 32-byte ESP-NOW packet → the bridge receives it, checks the CRC, and prints one line of JSON per packet over USB → this page parses that line and draws the hex dump, the decoded table, and the counters. The sequence number lets the page count gaps (lost packets); the radio reports the RSSI. The bridge’s line format is the shared format for the whole demo family — see PROTOCOL.md.

Known quirks:

  • If the antenna is loose, no packets arrive and the link shows LINK LOST. Check the u.FL first.
  • Both boards must be on the same channel (6). The firmware pins it; don’t change one without the other.
  • If the board won’t take new firmware: hold BOOT, tap RESET, release BOOT.
  • A bus-powered node can brown out on radio spikes — a decent USB bank helps.
  • Only one program can hold the serial port; close other serial monitors.

Put the firmware on the boards

One-time step per board. The XIAO C3 runs CircuitPython; you copy a code.py onto it.

  1. Install CircuitPython on each XIAO ESP32-C3 if it isn’t already (see the board page). The C3 has no CIRCUITPY drive, so files go over the serial/web workflow.
  2. Bridge board: copy firmware/bridge/code.py onto it. This is the board you plug into the laptop.
  3. TX board: copy firmware/tx/code.py onto the other one. Power it from a USB bank.
  4. Connect. Plug the bridge into the laptop, scroll up, click Connect bridge, and pick the port named USB JTAG/serial (or USB Serial Device on Windows). The TX board just needs power.

Label the boards “BRIDGE” and “TX” — they’re identical hardware, only the code.py differs. Keep a spare of each, pre-flashed.
