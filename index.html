Hardware

Two identical boards, nothing wired between them, and which firmware goes on each.

Two boards

RoleBoardExtrasPower
Bridge (receiver)XIAO ESP32-C3 running firmware/bridgeu.FL antennaLaptop USB-C
TX (sender)XIAO ESP32-C3 running firmware/txu.FL antennaUSB bank / laptop

The bridge is the only board the browser talks to. The TX node is untethered so a volunteer can carry it. A board is whichever firmware it was last given; the Firmware tab installs either.

Wiring

SignalPinNote
Bridge USBUSB-CTo the laptop — the only required connection
Antenna (both)u.FLClip on firmly — the only antenna the C3 has
TX powerUSB-CUSB bank or a second laptop port

No level shifting, no jumpers, no breadboard. The two boards talk over the air; nothing is wired between them.

Parts

  • 2× Seeed XIAO ESP32-C3, each with the u.FL antenna that ships with it.
  • USB-C data cable for the bridge (not charge-only), and a USB bank or second cable for the TX node.
  • Two labels: BRIDGE and TX. The boards are identical; only the code.py differs.

Things that bite

  • If the antenna is loose, no packets arrive and the link shows LINK LOST. Check the u.FL first.
  • Both boards pin Wi-Fi channel 6. Change one firmware’s channel and you must change the other.
  • A bus-powered node can brown out on radio spikes — a decent USB bank helps.
  • Only one program can hold the serial port; close other serial monitors before Connect.
  • If a board won’t take firmware: hold BOOT (B), tap RESET (R), release BOOT, then try again.
  • If the chooser shows no port, the cable is the usual suspect — many USB-C cables are charge-only.

The same tables live in wiring/wiring.md.

Put the firmware on the boards

Two roles, bridge and tx, each a single code.py written straight from this page. Chrome or Edge.

1. Plug in

Connect one XIAO ESP32-C3 over USB. If the instrument is connected to a board, this page disconnects it first.

2. Pick its job

Install bridge for the board that stays at the laptop and receives. Install TX for the board that will broadcast. Pick the port named USB JTAG/serial debug unit.

3. Wait for the first line

The page writes code.py over CircuitPython’s REPL, checks its size and CRC on the board, reboots it, and waits for the firmware’s first line. Then do the other board.

4. Connect

Leave the bridge plugged in, power the TX node from a USB bank, go back to the instrument and click Connect bridge. Or skip all of this: Try without hardware runs the whole page on a simulator.

About this demo

What it shows, how to run it in front of a room, and how the bytes get from the air to this page.

What it shows

“Wireless” isn’t magic — it’s just bytes with a checksum. One board broadcasts a fixed 32-byte packet a few times a second; a second board, plugged into the laptop, catches each one and shows it here: the raw bytes (colored by field), the decoded values, and how many packets arrive, how many go missing, and how strong the signal is.

Try this during the tour: walk the sending board toward the back of the room and watch last RSSI drop and the loss counter climb. Step between the two boards with your body and the little dot flashes as packets go missing. Hover a byte in the hex dump to show which field it belongs to.

How it works

TX broadcasts a 32-byte ESP-NOW packet → the bridge receives it, checks the CRC, and prints one line of JSON per packet over USB → this page parses that line and draws the hex dump, the decoded table, and the counters. The sequence number lets the page count gaps (lost packets); the radio reports the RSSI. The bridge’s line format and the payload layout are in PROTOCOL.md.

Known quirks:

  • Loss is counted from skipped sequence numbers, so a packet that arrives with a bad CRC counts as received and as a CRC fail, not as lost.
  • RSSI is whatever the radio reports for the last packet; it jumps around by a few dB even when nothing moves.
  • The simulator drops a sequence number now and then on purpose, so the loss counter has something to show.
